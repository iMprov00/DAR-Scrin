# Архитектура (MVP)

## Общий подход

Один модульный монолит на Django: шаблоны Django + HTMX, PostgreSQL, Docker Compose. Без React, микросервисов, Redis, Celery, DRF в MVP.

Бизнес-логика — в сервисном слое (не только во views), чтобы позже подключить `/api/v1/` без дублирования правил.

## Модули

| Модуль | Назначение |
|--------|------------|
| `accounts` | Пользователи, роли (в т.ч. совмещение), вход, деактивация и сброс сессий, обязательная смена пароля (допущение) |
| `directory` | Организация, подразделения, карточки сотрудников (дата рождения как источник возраста; без медответов) |
| `questionnaires` | Шаблоны анкет, версии, пункты, типы ответов, условия показа |
| `screenings` | Контейнер обследования, назначения, черновики/снимки ответов, статусы, аудит, проверка |

## Данные: анкеты

- Шаблон имеет версии со статусами `draft` / `published`.
- Публикация делает версию **неизменяемой**. Правки — через копию (новая draft-версия).
- Django Admin для шаблонов — только у специально уполномоченной роли.
- Пункты: коды, типы (да/нет, число, текст, один вариант), условия показа в БД.
- Не строить универсальный движок «любых форм» и визуальный конструктор.

## Данные: обследования

- **Контейнер обследования** — точка расширения под будущие разделы (медосмотр, итог), без проектирования этих разделов сверх задела.
- **Назначение** — сотрудник, срок, статус, неизменяемая ссылка на опубликованную версию шаблона, выбранная на дату назначения форма (до 65 / 65+) по дате рождения.
- Несколько параллельных назначений одному человеку — отдельные прохождения.
- Смена срока пишется в аудит (кто, когда, старое/новое значение); допустимые статусы для смены — см. допущения в [decisions.md](decisions.md).
- **Черновик ответов** — автосохранение в статусах, где редактирование разрешено.
- **Снимки (версии ответов)** — неизменяемые отправленные наборы; при повторной отправке после `returned` создаётся новый снимок, старый не меняется.
- Скрытые по условиям ответы не участвуют в текущей проверке/отправке, но не стираются из истории снимков без необходимости.

## Сервисный слой и события

Сервисы инкапсулируют переходы статусов, автосохранение, submit, возврат, «Проверено», отмену, смену срока.

Простой программный интерфейс событий без брокера/очереди/outbox:

- `assigned`
- `submitted`
- `returned`
- `reviewed`

Уведомления в мессенджеры и планировщик напоминаний о сроке в MVP не реализуются.

## Будущий API

Задел: префикс `/api/v1/`, те же сервисы. В MVP HTTP API и DRF не реализуются.

## Интерфейс

Русский UI. Вариант дизайна 1: белый фон, изумрудные акценты, компактная светлая боковая панель, удобные списки и фильтры, крупные элементы управления; телефон для сотрудника, рабочий стол для врача. Без пустых будущих разделов («Медосмотр», «Отчёты»).

## Безопасность с начала реализации

Обязательны уже на каркасе и дальше: сессии Django, CSRF, серверные проверки прав на каждое назначение. Не откладывать до выхода из тестового контура. TLS — до применения вне теста (см. [deployment.md](deployment.md)).

## Инфраструктура (задел на этапы реализации)

Совместимые поддерживаемые версии Python/Django/PostgreSQL фиксируются при реализации, не «latest наугад». Тесты только на PostgreSQL.

Предлагаемый (допущение) `TIME_ZONE=Asia/Barnaul` — единый пояс для возраста, срока и просрочки.
