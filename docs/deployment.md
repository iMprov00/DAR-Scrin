# Развёртывание (тестовая ВМ)

## Целевая среда

- Linux-ВМ для теста.
- Docker Compose: приложение + PostgreSQL (+ обратный прокси по схеме этапа реализации).
- Стек приложения: Django + Gunicorn за обратным прокси.
- Порт PostgreSQL **не** открывать наружу.
- `django runserver` **не** использовать как способ внешнего доступа на ВМ.
- HTMX и статика — **локально**, без CDN.
- Только **синтетические** данные. Реальные персональные/медицинские сведения не переносить.

## Конфигурация и секреты

- Секреты только в переменных окружения.
- В репозитории — `.env.example` **без значений**.
- С начала реализации (в том числе на тестовой ВМ): сессии Django, CSRF, серверные проверки прав на каждое назначение.
- До применения вне тестового контура дополнительно: ограничение попыток входа (троттлинг), TLS.
- Предлагаемый (допущение) часовой пояс приложения: `TIME_ZONE=Asia/Barnaul` — зафиксировать в настройках на этапе реализации после подтверждения.

## Обычный runbook (без уничтожения данных)

Типовые операции (конкретные команды фиксируются на этапе реализации Compose):

1. Проверить `.env` на ВМ (не коммитить).
2. Поднять/обновить стек Compose **без** удаления томов.
3. Применить миграции.
4. Собрать/раздать статику при необходимости.
5. Проверить доступ через обратный прокси и Gunicorn.
6. Перезапуск сервисов при сбое — снова **без** удаления томов.

**Запрещено в обычных инструкциях:** `docker compose down -v` — уничтожает тома с данными.

## Сохранность данных

После перезапуска контейнеров без удаления томов данные PostgreSQL (и загруженные файлы, если появятся) должны сохраняться.

## Резервное копирование

Резерв делает **сервер / администрирование ВМ**, не приложение. Приложение лишь документирует, что сохранять:

- дамп / том PostgreSQL;
- загруженные файлы (если появятся);
- конфигурацию развёртывания;
- секреты (вне git, по процедуре сервера).

Интерфейса резервного копирования в приложении в MVP нет.

## Краткий план отката

1. Остановить выкладку новой версии приложения (оставить БД и тома).
2. Вернуть предыдущий образ / тег приложения в Compose.
3. Поднять стек без `-v`.
4. Если миграции уже применены и несовместимы — выполнить заранее подготовленный план отката миграций **только** при наличии проверенного обратного пути; иначе восстановить БД из резервной копии сервера.
5. Проверить вход и ключевой сценарий назначения/чтения на синтетике.
6. Не применять «очистку томов» как способ отката.

## Боевое применение

До использования вне теста: подтверждённые бланки анкет, TLS, усиленная конфигурация безопасности, процедура резерва и восстановления на стороне сервера.
