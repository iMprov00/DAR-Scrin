# Тестирование

## Правила

- Тесты только на **PostgreSQL** (не SQLite как замена для приёмки домена).
- Новое поведение покрывать тестами. Этап не «готов» без фактических команд и результатов.
- Не фиксировать выдуманный процент покрытия и сроки разработки.
- На тестовой ВМ — только синтетические данные.
- Не печатать пароли и ответы анкет в логах тестов сверх необходимого идентификатора кейса.

## Матрица обязательных сценариев

| ID | Сценарий | Ожидание |
|----|----------|----------|
| T01 | Граница возраста 64 / 65 | По дате рождения и дате назначения в `TIME_ZONE`: до дня 65-летия — форма до 65; в день 65-летия и позже — форма 65+ |
| T02 | Параллельные назначения | Два назначения одному сотруднику изолированы: ответы, сроки, статусы не смешиваются |
| T03 | Правка после `returned` | Можно изменить любые пункты и отправить снова; предыдущий снимок неизменяем |
| T04 | Запрет правки после `reviewed` | Редактирование и автосохранение отклоняются |
| T05 | Неактивный пользователь | Вход запрещён; существующие сессии сброшены; история назначений сохранена |
| T06 | Заморозка версии шаблона | После публикации версия не меняется; назначение хранит ту же версию при поздних правках шаблона через копию |
| T07 | Скрытые старые ответы | После смены управляющего ответа скрытые значения не входят в проверку/новый снимок, но прошлые снимки целы |
| T08 | Атомарный submit | При ошибке/гонке нет «полуотправленного» состояния; снимок и статус согласованы |
| T09 | Гонка автосохранения после submit | Поздний autosave не портит отправленный снимок и статус |
| T10 | Сохранность томов Compose | Перезапуск стека без удаления томов сохраняет данные |
| T11 | Админ и прямая URL ответов | Администратор без полномочия не читает ответы по прямой ссылке |
| T12 | Перекрёстные запросы | Сотрудник A не читает/не пишет назначение сотрудника B; серверная проверка прав на каждое назначение |
| T13 | Допустимые переходы | Недопустимый переход статусов отвергается сервером |
| T14 | Просрочка (допущение включительности) | Для `assigned` / `draft` / `returned`: в день срока ещё не просрочено; со следующего календарного дня в `TIME_ZONE` — просрочено |
| T15 | Возврат: комментарий | Без комментария врача возврат невозможен; комментарий виден сотруднику |
| T15a | Возврат: новый срок (допущение) | Если допущение подтверждено — без нового срока возврат невозможен (дата может совпасть с прежней явно) |
| T16 | Отмена (допущение) | Если допущение подтверждено — до `reviewed` возможна с аудитом; записи не жёстко удаляются |
| T17 | Отсутствие ответа | Пустой пункт не трактуется как «нет» |
| T18 | CSRF и сессии | Запросы изменения состояния без CSRF отклоняются; работа идёт через сессии Django с начала реализации |
| T19 | Аудит смены срока | При изменении срока в журнале есть кто/когда/старое/новое значение и назначение |

## Уровни проверки

- **Модульные / сервисные** — переходы, выбор формы, скрытие пунктов, права.
- **Интеграционные на PostgreSQL** — submit, снимки, гонки по возможности.
- **Ручные на ВМ** — UI сотрудника/терапевта, прокси, сохранность после рестарта.

## Вне матрицы MVP

Медицинская интерпретация, баллы, API, уведомления, импорт сотрудников — не тестируются как реализованные функции, пока нет отдельной задачи.
