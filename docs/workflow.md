# Жизненный цикл назначения анкеты

## Часовой пояс и даты

- **Допущение до подтверждения:** предлагаемый `TIME_ZONE=Asia/Barnaul`.
- Единое правило: календарные сравнения (возраст, срок, просрочка, «сегодня») выполняются в этом поясе, а не по часовому поясу браузера.
- **Допущение до подтверждения:** день указанного срока **включителен**; просрочка начинается на **следующий** календарный день после даты срока.

## Статусы

| Код | Смысл |
|-----|--------|
| `assigned` | Назначено, заполнение ещё не начато |
| `draft` | Есть черновик (после первого успешного автосохранения) |
| `submitted` | Отправлено сотрудником |
| `returned` | Вернуто терапевтом на исправление; редактирование и автосохранение идут в этом статусе |
| `reviewed` | Терапевт отметил «Проверено» (для MVP терминальный) |
| `canceled` | Отменено (терминальный) |

## Допустимые переходы (согласованное ядро)

| Из | В | Кто / условие |
|----|---|----------------|
| `assigned` | `draft` | Сотрудник: первое успешное автосохранение |
| `assigned` | `submitted` | Сотрудник: отправка без промежуточного черновика (если допускается сервером) |
| `draft` | `submitted` | Сотрудник: отправка |
| `submitted` | `returned` | Терапевт: обязательный комментарий (виден сотруднику); см. допущение про новый срок |
| `submitted` | `reviewed` | Терапевт: «Проверено» |
| `returned` | `submitted` | Сотрудник: повторная отправка |
| `reviewed` | — | Переходов нет |
| `canceled` | — | Переходов нет |

Переходы проверяются **только на сервере**. Недопустимый переход — ошибка без изменения состояния. Серверные проверки прав — на каждое назначение.

### Отмена (допущение, не подтверждённое требование)

Пока **допущение**: из `assigned` / `draft` / `submitted` / `returned` → `canceled` с аудитом, без жёсткого удаления записей. Не выдавать за согласованное ТЗ до подтверждения.

## Просрочка

Просрочка **не статус**. Вычисляемый признак (с учётом допущения о включительности срока):

календарная дата «сегодня» в `TIME_ZONE` **строго позже** даты срока **и** статус ∈ {`assigned`, `draft`, `returned`}.

В день срока назначение ещё не просрочено. В статусах `submitted`, `reviewed`, `canceled` признак «нужно дозаполнить» по сроку не применяется.

## Возврат

При переходе `submitted` → `returned`:

1. **Согласовано:** комментарий врача обязателен и виден сотруднику.
2. **Допущение:** терапевт обязан указать новый срок (может явно совпасть с прежней датой).

В `returned` сотрудник может править **любые** пункты; автосохранение разрешено.

## Изменение срока

Отдельная операция (не только при возврате). В аудит пишутся: кто изменил, когда, старое значение срока, новое значение, идентификатор назначения. Содержание ответов в аудит не пишется.

### Допустимые статусы для смены срока (предложение, не согласовано)

Предлагается разрешить смену срока в `assigned`, `draft`, `returned`; запретить в `reviewed` и `canceled`; для `submitted` — уточнить отдельно. До подтверждения не считать обязательным правилом продукта.

## Снимки ответов

- Успешный `submitted` создаёт **неизменяемый** снимок ответов.
- Черновик после возврата не меняет предыдущий снимок.
- Повторная отправка создаёт новый снимок.
- После `reviewed` редактирование анкеты запрещено; снимки и факт проверки с комментарием доступны сотруднику на чтение.

## Скрытые ответы

Если управляющий ответ изменился и зависимые вопросы скрыты:

- скрытый старый ответ **не учитывать** в текущей проверке перед отправкой и в составе нового снимка;
- уже сохранённые значения в черновике/истории **не терять** без явной отдельной политики удаления (снимки прошлых отправок неизменяемы).

Отсутствие ответа не считать ответом «нет».

## Гонки автосохранения и submit

- Автосохранение подтверждается сервером или показывает ошибку.
- После перехода в `submitted` / `reviewed` / `canceled` черновые сохранения не должны портить отправленный снимок и статус.
- При конкуренции автосохранения и отправки сервер отклоняет устаревшее сохранение (проверка статуса и/или версии черновика).
- Отправка **атомарна**: либо создан снимок и статус `submitted`, либо состояние не изменилось.

## Выбор формы и версии

- Источник возраста — **дата рождения** в карточке сотрудника.
- Дата назначения в `TIME_ZONE` → полные годы по дате рождения → форма до 65 или 65+.
- В день исполнения 65 лет — форма 65+.
- Версия шаблона фиксируется в назначении и позже не пересчитывается.
