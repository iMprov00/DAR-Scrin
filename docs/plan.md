# План работ

## Правила параллельности

- Роли чатов: **дирижёр**, backend, интерфейс, QA/инфра. Пользователь переносит задания между чатами; чаты сами друг друга не вызывают.
- Обычно не больше **двух** рабочих задач одновременно.
- Одна ветка / worktree на задачу; иначе — последовательно в одной папке.
- Один владелец в момент времени: модели, миграции, зависимости, Docker Compose, базовые шаблоны.
- Контракты (URL, имена, сервисы, контекст шаблонов, статусы) фиксируются **до** параллельной вёрстки.
- Объединяет изменения только **дирижёр** после тестов; обновляет статусы в этом файле.
- Не объявлять этап готовым без фактических команд и результатов.

### Этап 1 — Каркас проекта

- **Статус:** готово
- **Исполнитель:** backend (отдельный чат)
- **Коммит приёмки:** `a372d96`
- **Содержание:** Django-проект, зависимости с зафиксированными совместимыми версиями, PostgreSQL, Docker Compose, настройки (в т.ч. сессии и CSRF), `.env.example` без значений, базовые URL/шаблоны-заготовки, входной каркас.
- **Зависимости:** этап 0
- **Врата приёмки:** контейнеры поднимаются; приложение отвечает через согласованный способ доступа для тестовой ВМ; секреты не в репозитории; PostgreSQL не открыт наружу; CSRF и сессии включены с каркаса.
- **Факт приёмки (дирижёр):** `docker compose` — db healthy, app Up, nginx `:8080`; `/login/` 200 + `csrftoken`; `/` 302→login; HTMX локально 200; PortBindings db пустые; `.env` в gitignore; `TIME_ZONE=Asia/Barnaul`, Session+CSRF middleware.
