# Функциональные требования (MVP)

## Роли

- **Сотрудник** — видит только свои назначения, анкеты и результаты проверки.
- **Терапевт** — видит всех сотрудников организации; назначает анкеты, меняет срок, отменяет, возвращает с комментарием, отмечает «Проверено».
- **Администратор** — учётные записи, подразделения, доступ. По умолчанию **не** видит медицинские ответы анкет, в том числе по прямой URL.
- Учётка может совмещать роли.
- Отдельное полномочие на правку шаблонов анкет в Django Admin не выдаётся всем обычным администраторам автоматически.
- Деактивация отключает вход и сессии; история обследований не удаляется.

## Основные сценарии

1. Администратор создаёт сотрудников вручную (в карточке — дата рождения как источник возраста; импорт из файла вне MVP).
2. Терапевт назначает анкету сотруднику со сроком. Несколько параллельных назначений одному человеку разрешены.
3. Система выбирает форму (до 65 / 65+) по полным годам на дату назначения в `TIME_ZONE` (предлагается `Asia/Barnaul`, см. [decisions.md](decisions.md)) по дате рождения и фиксирует версию шаблона неизменно.
4. Сотрудник заполняет анкету: автосохранение черновика, условные вопросы, проверка перед отправкой, отправка.
5. После отправки сотрудник только читает. Править можно только после возврата терапевтом.
6. Терапевт возвращает с **обязательным комментарием**, который виден сотруднику. Сотрудник правит любые пункты и отправляет снова. *(Обязательный новый срок при возврате — допущение, см. decisions.md.)*
7. Терапевт отмечает «Проверено»; сотрудник видит комментарий и факт проверки. Дальше правка анкеты запрещена.
8. Терапевт работает со списками: фильтры и вычисляемый признак просрочки.
9. Изменение срока фиксируется в аудите (кто, когда, старое/новое значение). Допустимые статусы для смены срока — предложение, не согласованное ТЗ (см. workflow.md / decisions.md).
10. Значимые действия пишутся в журнал без содержания ответов.

## Права доступа

| Действие | Сотрудник | Терапевт | Администратор (по умолчанию) |
|----------|-----------|----------|------------------------------|
| Свои назначения и ответы | да | — | нет |
| Чужие ответы / прямая URL к ответам | нет | да | нет |
| Назначение, срок, отмена | нет | да | нет (если нет роли терапевта) |
| Возврат / «Проверено» | нет | да | нет |
| Учётки, подразделения, дата рождения | нет | нет | да |
| Шаблоны в Django Admin | нет | нет | только по отдельному полномочию |

Права проверяются на сервере на уровне объекта **для каждого назначения**. С начала реализации обязательны сессии Django и CSRF (не откладывать до выхода из тестового контура).

Отмена назначения до `reviewed` — **допущение**, не подтверждённое требование (см. [decisions.md](decisions.md)).

## Правила анкет

- Две формы: до 65 лет и 65 лет и старше (бланки заказчика как «утверждённые Минздравом РФ»; актуальность не верифицирована).
- Официальные формулировки не выдумывать и не править; пунктам — стабильные коды. Точную расшифровку фото подтвердить до реального применения.
- В разработке допустим явно демонстрационный минимальный шаблон, не подменяющий официальную анкету.
- Источник возраста — дата рождения в карточке сотрудника. Базовая дата выбора формы — дата назначения в `TIME_ZONE`. Полные годы: в день 65-летия — форма 65+.
- Версия шаблона привязана к назначению и не пересчитывается.
- Типы пунктов в БД: да/нет, число, текст, один вариант. Условия показа — в БД.
- Отсутствие ответа ≠ ответ «нет».
- При смене управляющего ответа зависимые вопросы скрываются: скрытый старый ответ не учитывается в текущей проверке и отправке, но сохранённые снимки не теряются.

## Правила проверки и статусов

- После `submitted` — только чтение для сотрудника.
- Правка отправленной анкеты — только в `returned` с обязательным комментарием врача (виден сотруднику); править можно любые пункты; предыдущий отправленный снимок неизменяем.
- После `reviewed` редактирование запрещено.
- Медицинскую интерпретацию и балльные выводы **не** реализовывать.

Жизненный цикл и допустимые переходы — в [workflow.md](workflow.md).

## Границы MVP

**Входит:** ручное создание сотрудников (с датой рождения); вход; назначение и срок с аудитом изменений срока; параллельные назначения; черновик и автосохранение; условные вопросы; возврат с обязательным комментарием; «Проверено»; списки терапевта с просрочкой; версии шаблонов; журнал без ответов в логах; сессии Django, CSRF и объектные права с начала реализации.

**Не входит:** интерпретация и баллы; медосмотр и итоговое медзаключение; отчёты и выгрузки; конструктор анкет; импорт сотрудников; API/DRF; боты; уведомления; Redis; Celery; резерв в UI; React; микросервисы.
