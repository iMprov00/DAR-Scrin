# ДАР-Скрин

## Что это
Веб-сервис для организации, которая обследует собственных работников. Терапевт назначает анкету на выявление хронических неинфекционных заболеваний, работник заполняет её в сервисе, терапевт проверяет ответы и фиксирует результат проверки.

Первая версия рассчитана на одну организацию и одного терапевта, который работает со всеми сотрудниками. Развёртывание — локально, на Linux, начиная с тестовой ВМ.

## Что входит в MVP
- Ручное создание сотрудников администратором (в карточке — дата рождения; импорт из файла вне MVP).
- Вход сотрудника, терапевта и администратора; сессии Django, CSRF и объектные права — с начала реализации.
- Назначение анкеты, срок, изменение срока с аудитом; отмена — см. допущения в docs/decisions.md.
- Несколько одновременных назначений одному человеку — отдельные прохождения, ответы и сроки.
- Заполнение анкеты: черновик с автосохранением, условные вопросы, проверка перед отправкой, повторная отправка после возврата.
- Возврат терапевтом на исправление только с обязательным комментарием.
- Отметка «Проверено»; комментарий и факт проверки видны сотруднику.
- Рабочие списки терапевта с фильтрами и вычисляемым признаком просрочки.
- Версии шаблонов анкет в базе (черновик / опубликовано).
- Журнал значимых действий без содержания ответов в логах.

## Что не входит в MVP
- Медицинская интерпретация, балльные выводы и «рекомендованное заключение» системы.
- Медосмотр, общее итоговое медицинское заключение, дальнейшие этапы маршрута.
- Отчёты, выгрузки, визуальный конструктор анкет.
- Импорт сотрудников из файла.
- API / Django REST Framework, боты, уведомления в мессенджерах, Redis, Celery.
- Интерфейс резервного копирования в приложении.
- React и микросервисы.

Эти возможности учитываются в архитектуре (расширяемый контейнер обследования, общая бизнес-логика в сервисном слое, простой интерфейс событий, будущий префикс /api/v1/), но сейчас не реализуются.

## Роли
- Сотрудник: только свои назначения, анкеты и результаты проверки.
- Терапевт: все сотрудники организации; назначения, проверка, возврат, изменение срока, отмена.
- Администратор: учётные записи, подразделения, доступ. По умолчанию без доступа к ответам анкет, в том числе по прямой ссылке.
- Отдельное полномочие на правку шаблонов анкет в Django Admin не выдаётся всем обычным администраторам автоматически.

Одна учётная запись может совмещать роли. Деактивация отключает вход и сессии, история обследований не удаляется.

## Стек
Python, Django, PostgreSQL, шаблоны Django, HTMX, Docker Compose. Один модульный монолит. Тесты только на PostgreSQL. Интерфейс на русском.

## Важные ограничения
Анкеты основаны на бланках, предоставленных заказчиком как утверждённые Минздравом РФ (формы до 65 лет и 65 лет и старше). Актуальность редакции не верифицирована. Официальные формулировки нельзя выдумывать или править. Перед применением в реальных обследованиях точную расшифровку бланков нужно подтвердить. На тестовой ВМ — только синтетические данные. Система не ставит диагноз и не заменяет врача.
